## Signal

## Signal

(世, p=0.99) **Event sourcing is not “recording events.” It is choosing events as the authoritative representation of state.**

(世, p=0.99) The defining equation is:

$$
State_t = fold(apply,\ State_0,\ Events_{\le t})
$$

(世, p=0.99) If deleting every database table, cache, search index, follower count, timeline, and materialized view still leaves enough durable information to reconstruct them from the event history, you have the essential shape of event sourcing.

(世, p=0.99) If the events merely describe what happened while some separately-mutated database remains authoritative, you have **structured logging**, not event sourcing.

### Event sourcing vs nearby ideas

| Technique | Authoritative truth | Can state be rebuilt from it? | Mutation normal? |
|---|---|---:|---:|
| Structured logs | Current DB/state | Usually no | Yes |
| Audit log | Current DB + historical audit | Sometimes partially | Yes |
| CDC | Database mutations | Usually yes-ish | DB remains authority |
| Transaction journal/WAL | Database implementation state | Internally | Yes |
| Event-driven architecture | Depends | Not necessarily | Depends |
| **Event sourcing** | **Domain events** | **Yes, deliberately** | **Events: no** |
| Projection/materialized view | Event history | Rebuilt from events | Yes, freely |

(世, p=0.99) A Kafka topic full of JSON objects is therefore not automatically event sourcing.

(世, p=0.99) An append-only `.edn` file absolutely can be event sourcing.

### The core axioms

(世, p=0.98) I would reduce event sourcing to six axioms.

**1. Events describe facts, not intentions.**

(世, p=0.99) A command says:

```clojure
{:command/type :post/delete
 :post/id "p1"}
```

(世, p=0.99) An event says:

```clojure
{:event/type :post/deleted
 :post/id "p1"}
```

(世, p=0.97) Commands may fail. Events assert that something became true.

**2. Committed events are immutable.**

(世, p=0.99) You do not correct history by editing history.

(世, p=0.99) You append another fact:

```clojure
{:event/type :post/restored
 :post/id "p1"
 :restores "event-uuid-that-deleted-it"}
```

**3. Events are authoritative.**

(世, p=0.99) Derived state is disposable.

(世, p=0.99) A projection can be deleted and recreated without losing domain information.

**4. Replay has deterministic semantics.**

(世, p=0.99) Given the same relevant event set, schemas, ordering rules, and projector version, you get the same state.

**5. Every event has stable identity.**

(世, p=0.99) This permits deduplication, provenance, causality, replication, and idempotent consumers.

**6. Enough ordering information exists to resolve state.**

(世, p=0.99) This does **not** imply a global total order.

(世, p=0.99) It implies that wherever order changes meaning, the system can determine that order.

### What must an event possess?

(世, p=0.94) There is no standards-mandated event structure, but logically an event needs four things:

```clojure
{:event/id     ...
 :event/type   ...
 :event/order  ...
 :event/data   ...}
```

(世, p=0.99) In a system intended to survive partitioning and merging, I would make this more explicit:

```clojure
{:event/id       #uuid "..."
 :event/type     :post/created
 :event/version  1

 :stream/id      "post:p-123"
 :stream/seq     1

 :event/causes   []
 :event/actor    "user:u-42"
 :event/subject  "post:p-123"
 :event/at       "2026-08-08T20:00:00Z"

 :event/data
 {:author/id "user:u-42"
  :text      "hello"}}
```

(世, p=0.99) `:event/id` answers **which fact is this?**

(世, p=0.99) `:event/type` + `:event/version` answer **how should I interpret it?**

(世, p=0.99) `:stream/id` + `:stream/seq` answer **where does this fact sit in the state transition history of this thing?**

(世, p=0.99) `:event/causes` answers **which prior facts causally preceded this fact?**

(世, p=0.97) `:event/at` is useful metadata, but a wall-clock timestamp is generally **not a safe ordering mechanism**.

(世, p=0.99) UUID + causal IDs are extremely useful, but there is one important addition to your intuition: **they do not by themselves necessarily produce deterministic ordering between concurrent events.**

(世, p=0.99) Suppose these are concurrent:

```clojure
A -> user follows Bob
B -> user blocks Bob
```

(世, p=0.99) Neither causes the other.

(世, p=0.99) Your system must define whether that concurrency is harmless, commutative, rejected, resolved using stream revisions, or resolved through some deterministic conflict rule.

### Events naturally form a graph

(世, p=0.98) A useful model is:

```text
                   ┌── post-created ── reaction-added
user-created ──────┤
                   └── follow-created ── follow-ended

dm-thread-created ─── message-sent ─── message-retracted
```

(世, p=0.99) There are several different relationships here, and conflating them causes design problems:

```clojure
:event/causes      ;; causal DAG
:stream/id         ;; same logical object's history
:stream/seq        ;; ordering inside that stream
:correlation/id    ;; same operation/workflow
:event/actor       ;; who caused it
:event/subject     ;; thing affected
```

(世, p=0.99) Causality gives you a **partial order**.

(世, p=0.99) Stream sequence commonly gives you a **local total order**.

(世, p=0.97) A global total order is optional.

### Sourcing state

(世, p=0.99) The essential operation is a fold:

```clojure
(reduce apply-event initial-state events)
```

(世, p=0.99) For example:

```clojure
(defn apply-event [state event]
  (case (:event/type event)

    :user/created
    (assoc-in state
              [:users (get-in event [:event/data :user/id])]
              (get event :event/data))

    :post/created
    (assoc-in state
              [:posts (get-in event [:event/data :post/id])]
              (get event :event/data))

    :post/deleted
    (assoc-in state
              [:posts (:event/subject event) :deleted?]
              true)

    state))
```

(世, p=0.99) A snapshot is therefore:

```text
events ──fold──> state
```

(世, p=0.99) A snapshot may accelerate replay:

```text
events 1..5,000,000
          ↓
      snapshot
          +
events 5,000,001..now
          ↓
        state
```

(世, p=0.98) But the snapshot is ordinarily a cache/checkpoint, not historical authority.

(世, p=0.99) This:

```clojure

{:event/id "...2" ...}
{:event/id "...3" ...}
```

(世, p=0.99) can be genuinely appended.

(世, p=0.99) This:

```clojure
[
 {...}
 {...}
]
```

(世, p=0.99) requires rewriting the enclosing collection whenever an event is added.

(己, p=0.98) Here is a dependency-free NBB implementation with:

- append-only creation/writes
- UUID identity
- logical streams
- per-stream sequence numbers
- causal IDs
- event schema validation
- per-event payload schemas
- strict UUID collision detection
- stream revision conflict detection
- deduplication
- idempotent projection generation
- atomic projection replacement

```clojure
(ns ledger
  (:require
   [cljs.reader :as reader]
   [clojure.string :as str]
   ["fs" :as fs]))

;; ---------------------------------------------------------------------------
;; schema
;; ---------------------------------------------------------------------------

(def uuid-re
  #"(?i)^[0-9a-f]{8}-[0-9a-f]{4}-[1-5][0-9a-f]{3}-[89ab][0-9a-f]{3}-[0-9a-f]{12}$")

(defn uuid-string? [x]
  (and (string? x)
       (boolean (re-matches uuid-re x))))

(defn positive-integer? [x]
  (and (number? x)
       (= x (js/Math.floor x))
       (pos? x)))

(defn uuid-vector? [x]
  (and (vector? x)
       (every? uuid-string? x)))

(def base-event-schema
  {:event/id      uuid-string?
   :event/type    keyword?
   :event/version positive-integer?
   :event/stream  string?
   :event/seq     positive-integer?
   :event/causes  uuid-vector?
   :event/actor   string?
   :event/subject string?
   :event/at      string?
   :event/data    map?})

;; Tiny example domain.
;;
;; The schema system is deliberately boring. Replacing this with Malli,
;; Spec, Schema, etc. does not change the event-sourcing model.

(def event-data-schemas
  {:counter/added
   {:amount number?}

   :counter/subtracted
   {:amount number?}})

(defn fail! [message data]
  (throw (ex-info message data)))

(defn validate-map! [schema value label]
  (when-not (map? value)
    (fail! (str label " must be a map")
           {:value value}))

  (doseq [[k predicate] schema]
    (when-not (contains? value k)
      (fail! (str label " missing " k)
             {:key k
              :value value}))

    (when-not (predicate (get value k))
      (fail! (str label " invalid " k)
             {:key k
              :value (get value k)})))

  value)

(defn validate-event! [event]
  (validate-map! base-event-schema event "event")

  (let [event-type (:event/type event)
        schema     (get event-data-schemas event-type)]

    (when-not schema
      (fail! "unknown event type"
             {:event/type event-type}))

    (validate-map! schema
                   (:event/data event)
                   (str event-type " data")))

  event)

;; ---------------------------------------------------------------------------
;; ledger storage
;; ---------------------------------------------------------------------------

(defn new-ledger! [file]
  ;; "wx" means create exclusively; do not silently overwrite history.
  (let [fd (fs/openSync file "wx")]
    (fs/closeSync fd))
  file)

(defn read-ledger [file]
  (if-not (fs/existsSync file)
    []
    (->> (fs/readFileSync file "utf8")
         str/split-lines
         (remove str/blank?)
         (mapv reader/read-string))))

;; ---------------------------------------------------------------------------
;; canonicalization
;; ---------------------------------------------------------------------------

(defn canonical-events [events]
  (let [{:keys [by-id slots]}
        (reduce
         (fn [{:keys [by-id slots] :as acc} event]
           (validate-event! event)

           (let [id   (:event/id event)
                 slot [(:event/stream event)
                       (:event/seq event)]
                 old-event (get by-id id)
                 old-id    (get slots slot)]

             (cond
               ;; Exact duplicate:
               ;; harmless replication/delivery duplication.
               (= old-event event)
               acc

               ;; Same UUID, different content:
               ;; catastrophic identity collision/corruption.
               old-event
               (fail! "same event UUID has different contents"
                      {:event/id id
                       :first old-event
                       :second event})

               ;; Two different events claiming the same stream revision:
               ;; concurrency/conflict which must not be silently resolved.
               old-id
               (fail! "stream sequence conflict"
                      {:slot slot
                       :first-event/id old-id
                       :second-event/id id})

               :else
               {:by-id (assoc by-id id event)
                :slots (assoc slots slot id)})))

         {:by-id {}
          :slots {}}
         events)]

    (->> by-id
         vals

         ;; This demo's domain streams are independent counters.
         ;; Therefore order between different streams is irrelevant.
         ;;
         ;; Inside a stream, seq is authoritative.
         (sort-by
          (juxt :event/stream
                :event/seq
                :event/id))

         vec)))

;; ---------------------------------------------------------------------------
;; append
;; ---------------------------------------------------------------------------

(defn append-event! [file event]
  (validate-event! event)

  (let [existing  (canonical-events (read-ledger file))
        old-by-id (into {}
                        (map (juxt :event/id identity))
                        existing)

        old-event (get old-by-id (:event/id event))

        old-slot
        (some
         #(when (and
                 (= (:event/stream %)
                    (:event/stream event))
                 (= (:event/seq %)
                    (:event/seq event)))
            %)
         existing)]

    (cond
      ;; Retry of exactly the same append.
      (= old-event event)
      :already-present

      ;; Identity collision.
      old-event
      (fail! "event UUID collision"
             {:old old-event
              :new event})

      ;; Optimistic concurrency failure.
      old-slot
      (fail! "stream revision already occupied"
             {:old old-slot
              :new event})

      :else
      (do
        (fs/appendFileSync
         file
         (str (pr-str event) "\n")
         "utf8")

        :appended))))

;; ---------------------------------------------------------------------------
;; event construction
;; ---------------------------------------------------------------------------

(defn make-event
  [{:keys
    [event/type
     event/version
     event/stream
     event/seq
     event/causes
     event/actor
     event/subject
     event/data]}]

  (validate-event!
   {:event/id      (str (random-uuid))
    :event/type    type
    :event/version (or version 1)
    :event/stream  stream
    :event/seq     seq
    :event/causes  (or causes [])
    :event/actor   actor
    :event/subject subject
    :event/at      (.toISOString (js/Date.))
    :event/data    data}))

;; ---------------------------------------------------------------------------
;; projection
;; ---------------------------------------------------------------------------

(defn apply-event [state event]
  (let [stream (:event/stream event)
        amount (get-in event [:event/data :amount])]

    (case (:event/type event)

      :counter/added
      (update state stream (fnil + 0) amount)

      :counter/subtracted
      (update state stream (fnil - 0) amount)

      (fail! "projector does not understand event"
             {:event event}))))

(defn project [events]
  (let [events (canonical-events events)]

    {:projection/version 1

     ;; Useful provenance.
     :projection/event-count (count events)

     ;; Materialized state.
     :projection/state
     (reduce apply-event
             {}
             events)}))

(defn write-atomically! [file value]
  (let [tmp (str file ".tmp")]
    (fs/writeFileSync
     tmp
     (str (pr-str value) "\n")
     "utf8")

    (fs/renameSync tmp file))

  value)

(defn project! [ledger-file projection-file]
  (let [projection
        (-> ledger-file
            read-ledger
            project)]

    (write-atomically!
     projection-file
     projection)))

;; ---------------------------------------------------------------------------
;; tiny CLI
;; ---------------------------------------------------------------------------

(def args
  (vec (drop 2 js/process.argv)))

(case (first args)

  "new"
  (println
   (new-ledger! (second args)))

  "emit"
  (let [[_ file event-edn] args
        event (-> event-edn
                  reader/read-string
                  make-event)]

    (append-event! file event)
    (println (pr-str event)))

  "project"
  (let [[_ ledger-file projection-file] args]
    (println
     (pr-str
      (project! ledger-file
                projection-file))))

  (println
   "usage:"
   "nbb ledger.cljs new events.edn"
   "nbb ledger.cljs emit events.edn '<event-edn>'"
   "nbb ledger.cljs project events.edn state.edn"))
```

## Countermoves

(世, p=0.99) The strongest correction I would make to this:

> “It shouldn't really matter how the events are distributed across ledger files, as long as each event has a UUID to dedupe ledgers, and causal IDs.”

is:

> **It shouldn't matter how events are physically distributed, provided identity, causal dependency, and every order-sensitive relationship can be reconstructed deterministically.**

(世, p=0.99) UUID solves:

```text
Have I seen this exact event before?
```

(世, p=0.99) Causal references solve:

```text
Must event A precede event B?
```

(世, p=0.99) Neither necessarily solves:

```text
A and B are concurrent.
They both mutate the same logical object.
What happens?
```

(世, p=0.99) That is why I would retain something resembling:

```clojure
:event/id
:event/causes

:stream/id
:stream/seq
```

(世, p=0.98) Or replace `stream/seq` with a more sophisticated concurrency model if you deliberately want branching histories.

### A useful deeper abstraction

(己, p=0.96) I think the interesting architecture underneath what you're describing is not actually:

```text
one ledger
vs
many ledgers
```

(己, p=0.97) It is:

```text
             immutable event set
                    +
             causal/order graph
                    │
          ┌─────────┼─────────┐
          ▼         ▼         ▼
       ledger     ledger     ledger
       layout     layout     layout

          physical representations
```

(己, p=0.98) The **event graph is the thing**.

(己, p=0.97) Files are containers for pieces of it.

(世, p=0.97) A “complete ledger” can consequently be a **derived union view** rather than an independently authoritative second copy:

```text
source ledger A ──┐
source ledger B ──┼──► complete-ledger projection
source ledger C ──┘
```

(世, p=0.99) That avoids having two competing sources of truth.

(己, p=0.97) I would make the ontology something like:

```text
Event
  immutable domain fact

Event graph
  identity + causality + ordering relationships

Ledger
  append-only physical collection of events

Stream
  logical ordered history concerning an aggregate/topic

Projection
  deterministic interpretation of event graph

Snapshot
  cached projection checkpoint

Derived ledger
  projection whose output is itself an event-oriented subset/union/index
```

(己, p=0.98) That separation buys you something important: **ledger topology becomes an operational concern instead of contaminating domain semantics.**
