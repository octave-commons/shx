# Methodology vs Process

A **process** is the repeatable sequence of work; a **methodology** is the set of principles and techniques that explains how to design, choose, and carry out that work.


| Aspect | Process | Methodology |
| :-- | :-- | :-- |
| Primary question | “What happens next?” | “How and why should we approach this?” |
| Form | Ordered activities, handoffs, decisions, outputs | Principles, practices, methods, tools, and selection criteria |
| Purpose | Consistent execution | Effective, context-appropriate execution |
| Repeatability | Usually highly repeatable and automatable | Adapted to the situation, though it can guide repeatable processes |
| Example | Ticket → implement → review → test → deploy | Agile/Lean practices, test-driven development, domain-driven design |

## In software terms

Your **release process** might be:

1. Plan work
2. Implement
3. Run CI
4. Review
5. Deploy
6. Monitor

Your **methodology** might say: work in small vertical slices, prioritize feedback, automate regression tests, use feature flags for risky changes, and treat production telemetry as part of validation.

So the methodology influences *how* each process step is performed and when its practices are appropriate. A methodology can contain several processes; one process can be used under different methodologies.[^1_1][^1_2]

## Practical shorthand

- Process = **workflow / operational recipe**
- Methodology = **reasoned approach / playbook for choosing and applying methods**

For an ECS project: “Run system updates in a defined phase order” is a process. “Prefer data-oriented, deterministic, composable systems with explicit event boundaries” is methodology.

# procedure

A **procedure** is the specific, documented way to perform a task: precise instructions, in a defined order, often including roles, tools, conditions, and expected results. It answers: **“Exactly how do we do this?”**[^2_1][^2_2]

## Relationship

$$
\text{Methodology} \rightarrow \text{Process} \rightarrow \text{Procedure}
$$

- **Methodology:** guiding principles and techniques—why and how you approach work.
- **Process:** the end-to-end flow that produces an outcome—what occurs across the work.
- **Procedure:** the detailed instructions for one activity or step—how a person performs it.[^2_3][^2_4]


## Software example

**Process:** Release a service: merge code → validate → deploy → monitor.

**Procedure:** Deploy to production:

1. Confirm CI passed and the release is approved.
2. Tag the commit and build the immutable artifact.
3. Deploy first to the canary environment.
4. Check error rate, latency, and key business signals for the specified interval.
5. Promote or roll back according to defined thresholds.

In other words, the process is “releasing software”; the procedure is the runbook for executing a particular part of that release safely.
